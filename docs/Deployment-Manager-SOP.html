Azure Local Deployment Manager Standard Operating Procedure

Purpose: Use this procedure to execute and monitor the approved Azure Local Phase 1 onboarding workflow through the Deployment Manager.

1. Normal Workflow Sequence

Stage Name Expected Action
1.1 Input and Build Validation Run validation. Correct input, package, naming, address, or readiness failures before proceeding.
1.2B Ensure HCN Desired State Review the planned node changes. Approve only authorized desired-state changes. Resume after an approved reboot if required.
1.3 Azure Local Node Bootstrap Readiness Validate Azure Government context, subscription, providers, resource group, endpoints, and node readiness.
1.4 Azure Arc Machine Registration and Validation Approve and start or resume the factory-owned Native Arc Registration Session. Validate Arc registration and node health.

2. Recommended Operator Procedure

  1. Start launcher\Start-AzureLocalDeploymentManager.ps1.
  2. Review the manager summary and Next Recommended Action.
  3. Select 1 - Continue Recommended Workflow Action for normal workflow progression.
  4. Use 2 - Plan Current/Next Stage when a non-mutating review is required.
  5. Use 3 - Show Current Workflow Status to review stage gates and saved workflow state.
  6. Use 5 - View Last Failure and Evidence when a stage fails or becomes blocked.
  7. Use 6 - Show Workflow Map to confirm the current workflow position.

3. Approval and Pause Procedure

  1. Review the operation, node, approval type, and stated reason.
  2. Confirm the action is authorized under local procedures.
  3. Select Continue Recommended Workflow Action.
  4. Enter the requested approval confirmation exactly as prompted.
  5. Allow the manager to resume using the saved Run ID and workflow checkpoint.
Do not manually alter deployment-state files, approval records, operation checkpoints, reports, or evidence files.

4. Native Arc Registration Procedure

  1. Complete Stages 1.1 through 1.3 successfully.
  2. Review Stage 1.4 readiness and pending registration approval.
  3. Use the recommended action to approve and start the Native Arc Registration Session.
  4. If the workflow pauses for interactive authentication, return to the manager and use the recommended action to resume the saved session.
  5. Do not launch a separate manual node-side Arc registration workflow while the factory session is active.

5. Status and Outcome Meanings

Outcome Meaning
PASSED The operation completed successfully without a reported desired-state change.
SKIPPED The desired state already existed or no action was required.
CHANGED The operation successfully modified desired state.
PAUSED Workflow continuation requires operator approval, reboot completion, or interactive authentication.
FAILED An operation or validation failed. Review sanitized evidence and use approved corrective procedures.

6. Reports and Evidence

Every factory run produces a run-scoped report set:

artifacts\<site>\<RunId>\
    deployment-state.json
    execution-events.jsonl
    reports\deployment-report.html
    reports\deployment-report.json
    evidence\
  • deployment-report.html is the human-readable execution timeline.
  • deployment-report.json is the machine-readable report.
  • execution-events.jsonl records run, resume, operation, reboot, pause, failure, and completion events.
  • evidence contains safe run-scoped JSON evidence.

7. Security and Data Handling

  • Do not place credentials, passwords, tokens, secrets, or device codes into reports, evidence, tickets, or notes.
  • Use only authorized site inputs and approved operator accounts.
  • Follow organizational handling, records, access, need-to-know, security, and release procedures.
  • Escalate blocked workflow conditions through the appropriate technical and command channels.
